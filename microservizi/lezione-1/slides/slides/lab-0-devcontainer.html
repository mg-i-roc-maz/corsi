0.4 · Il Dev Container

Che cos'è

Un ambiente di sviluppo dentro un container Docker. VS Code si «sposta» dentro il container, dove Node 22 e le estensioni sono già installati.

Sul tuo computer servono solo Docker Desktop e VS Code con l'estensione Dev Containers. La configurazione è in .devcontainer/devcontainer.json.

1

Avvia Docker Desktop e aspetta che sia pronto

2

In VS Code apri la cartella lezione-1/start

3

In basso a destra compare l'avviso: clicca Reopen in Container. Se non compare: apri la palette dei comandi con Cmd+Shift+P (Mac) o Ctrl+Shift+P (Windows, Linux) e scegli «Dev Containers: Reopen in Container»

4

La prima volta servono alcuni minuti: scarica l'immagine e lancia npm install da solo

5

Sei dentro quando in basso a sinistra leggi Dev Container: Corso microservizi

node -v → v22.x cd monolith → npm run dev → http://localhost:3000

"Reopen in Container" significa: riapri questa stessa cartella, ma con VS Code collegato a un container. I file restano sul computer dello studente (la cartella viene montata nel container), mentre terminale, Node e npm girano dentro il container. Per questo node -v dà 22 anche se sul computer Node non è installato. Le porte 3000 e 3001 sono inoltrate automaticamente (forwardPorts), quindi REST Client e il browser raggiungono localhost come al solito. Per tornare all'apertura normale: palette dei comandi → "Dev Containers: Reopen Folder Locally". Su Mac F1 funziona solo con il tasto fn (fn+F1); in alternativa menu View → Command Palette, oppure clic sull'icona verde >< in basso a sinistra. Problema tipico: Docker Desktop non avviato, l'errore dice che non riesce a connettersi al daemon Docker.
