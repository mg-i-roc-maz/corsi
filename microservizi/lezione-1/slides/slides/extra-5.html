Validazione degli ordini

Nel monolite, aggiungi uno schema a POST /orders:

  • customerEmail obbligatoria, formato email
  • items: array con almeno un elemento
  • ogni elemento: productId stringa, quantity intero ≥ 1
  • nessun campo in più

Prendi spunto da productInputSchema. Per l'email: format: "email".

Per riflettere: lo schema non può controllare che il prodotto esista. Perché? E chi lo farà quando catalog sarà separato?

Soluzione, in monolith/src/orders/routes.ts: const createOrderSchema = { type: "object", required: ["customerEmail", "items"], additionalProperties: false, properties: { customerEmail: { type: "string", format: "email" }, items: { type: "array", minItems: 1, items: { type: "object", required: ["productId", "quantity"], additionalProperties: false, properties: { productId: { type: "string" }, quantity: { type: "integer", minimum: 1 } } } } } } as const; e poi app.post("/orders", { schema: { body: createOrderSchema } }, async (request, reply) => { ...codice invariato... }). Riflessione: lo schema controlla solo la forma dei dati, non lo stato del sistema; l'esistenza del prodotto la sa solo chi possiede i prodotti. Quando catalog sarà separato, orders dovrà chiederlo a catalog via HTTP (lezione 3).
