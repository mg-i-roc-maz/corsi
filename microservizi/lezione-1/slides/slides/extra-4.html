Errori in formato uniforme

Oggi l'API risponde agli errori in tre formati diversi. Per chi la usa, in particolare un altro servizio, ne serve uno solo: { error, details? }.

SituazioneCodiceCorpo
Rotta inesistente404{"error":"Rotta GET /prodotti inesistente"}
Dati non validi400{"error":"Dati non validi","details":[...]}
Errore imprevisto500{"error":"Errore interno"}

Suggerimenti: in app.ts usa app.setNotFoundHandler e app.setErrorHandler<FastifyError>; error.validation è un array con instancePath e message.

Soluzione, in app.ts dopo app.register(productRoutes): import Fastify, { type FastifyError, type FastifyInstance } from "fastify"; app.setNotFoundHandler((request, reply) => { reply.code(404).send({ error: `Rotta ${request.method} ${request.url} inesistente` }); }); app.setErrorHandler<FastifyError>((error, request, reply) => { if (error.validation) { return reply.code(400).send({ error: "Dati non validi", details: error.validation.map((v) => `${v.instancePath || "body"} ${v.message}`) }); } request.log.error(error); return reply.code(500).send({ error: "Errore interno" }); }); Riflessione: nel 500 non si manda il messaggio originale al client perché può contenere nomi di tabelle, percorsi di file o dati di altri utenti; il dettaglio resta nel log.
