Aggiornamento parziale con PATCH

Con PUT si inviano tutti i campi anche per cambiare solo il prezzo. Aggiungi PATCH /products/:id, che aggiorna solo i campi presenti.

  • Nuova funzione store.patch(id, changes) con lo spread { ...vecchio, ...modifiche }
  • Schema come productInputSchema ma senza campi obbligatori e con minProperties: 1
  • Togli il default di description, o ogni PATCH la svuoterebbe
  • Tipo del corpo: Partial<ProductInput>

Atteso

{ "priceCents": 7990 }
→ 200, nome invariato
{ }
→ 400
{ "priceCents": -1 }
→ 400
p-999
→ 404

Soluzione. In store.ts: export function patch(id: string, changes: Partial): Product | undefined { const current = products.get(id); if (!current) return undefined; const product: Product = { ...current, ...changes, id }; products.set(id, product); return product; } (l'id in fondo impedisce di cambiarlo). In schemas.ts: export const productPatchSchema = { ...productInputSchema, required: [], minProperties: 1, properties: { ...productInputSchema.properties, description: { type: "string", maxLength: 500 } } } as const; In routes.ts: app.patch<{ Params: IdParams; Body: Partial }>("/products/:id", { schema: { params: idParamSchema, body: productPatchSchema } }, async (request, reply) => { const product = store.patch(request.params.id, request.body); if (!product) return reply.code(404).send({ error: "Prodotto non trovato" }); return product; }). Riflessione: due utenti, uno fa PATCH sul prezzo e l'altro un PUT basato sulla versione vecchia: il PUT riporta indietro il prezzo. È il lost update, lo ritroveremo con cache e consistenza.
